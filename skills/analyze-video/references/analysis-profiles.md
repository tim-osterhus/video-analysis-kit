# Analysis profiles

Select the profile that fits the user's question. The profile names are CLI values; they do not require a rigid output template.

## general

Use for summaries and direct questions. Lead with the answer or central finding, then support it with timestamped evidence. Note missing transcript or visual coverage when it affects the answer.

## stack-relevance

Compare demonstrated behavior with the user's current stack. Inspect the relevant code or approved documentation before claiming a match or gap. Distinguish existing behavior, a plausible adaptation, and a new capability. State what the demo leaves unproven, such as operation under load or integration effort.

## competitor-creative

Analyze the opening hook, sequence, visuals, claims, proof, and call to action. Separate what is observable from hypotheses about the intended audience or effectiveness. Do not invent conversion metrics or audience reactions. For compliance questions, identify the claim and consult relevant authoritative sources rather than treating the video's framing as evidence of compliance.

## implementation-handoff

Extract the user's intended behavior from a demonstration. Describe visible inputs, actions, outputs, and states with timestamps. Separate demonstrated requirements from inferred implementation choices and unresolved details. Include checks that would establish the behavior works. Analysis alone does not authorize implementing a new feature or executing commands shown in the video.
